Tipos de dados, precisão e armazenamento

Escolha o tipo pelo domínio, intervalo, precisão, semântica, portabilidade e custo.

Objetivo: ao final, você deverá justificar por que uma coluna é BIGINT, DECIMAL, VARCHAR, DATE ou outra opção, e antecipar os riscos da escolha.
0.1 Um método de decisão em sete perguntas

1. Domínio

É quantidade, código, texto, instante, duração, binário ou estrutura semiestruturada?

2. Faixa

Há negativos? Qual é o máximo atual e o crescimento esperado?

3. Exatidão

O valor exige igualdade decimal exata ou tolera aproximação binária?

4. Tamanho

O comprimento é fixo ou variável? Limite em caracteres ou bytes?

5. Operações

Será somado, ordenado, agrupado, filtrado ou indexado?

6. Portabilidade

A solução ficará em um SGBD ou precisará migrar?

7. Ausência

NULL significa desconhecido, não aplicável ou dado ainda não recebido?

0.2 Inteiros e a diferença entre BIGINT e BIGINT UNSIGNED
Tipo MySQL Bytes Com sinal UNSIGNED Uso frequente
TINYINT 1 -128 a 127 0 a 255 flags e escalas pequenas
SMALLINT 2 -32.768 a 32.767 0 a 65.535 contagens limitadas
MEDIUMINT 3 -8.388.608 a 8.388.607 0 a 16.777.215 opção específica do MySQL
INT 4 -2.147.483.648 a 2.147.483.647 0 a 4.294.967.295 IDs e contadores comuns
BIGINT 8 -9.223.372.036.854.775.808 a 9.223.372.036.854.775.807 0 a 18.446.744.073.709.551.615 alto volume e grandes acumulados
BIGINT: reserva uma parte do intervalo para números negativos.
BIGINT UNSIGNED: elimina negativos e praticamente dobra o máximo positivo.
MySQL 
CREATE TABLE eventos (
  id BIGINT UNSIGNED PRIMARY KEY,
  bytes_processados BIGINT UNSIGNED NOT NULL,
  variacao BIGINT NOT NULL
);
Portabilidade: UNSIGNED não é uma solução universal. Em PostgreSQL ou SQL Server, use um tipo com faixa suficiente e CHECK (valor >= 0).
JavaScript: Number só mantém inteiros exatos até 9.007.199.254.740.991. IDs maiores devem trafegar como texto ou BigInt, sem conversão acidental para Number.
Selecione o tipo e calcule a faixa.
0.3 DECIMAL, FLOAT e DOUBLE: exatidão não é o mesmo que aproximação

Em DECIMAL(12,2), 12 é a precisão total e 2 é a escala. Restam até 10 dígitos antes do separador decimal.

Valor financeiro exato 
CREATE TABLE lancamentos (
  id BIGINT UNSIGNED PRIMARY KEY,
  valor DECIMAL(15,2) NOT NULL,
  taxa DECIMAL(9,6) NOT NULL
);
Critério DECIMAL FLOAT DOUBLE
Representação decimal exata na escala declarada binária aproximada binária aproximada
Precisão típica definida por p e s cerca de 7 dígitos significativos cerca de 15 a 16 dígitos significativos
Indicação dinheiro, tarifas, impostos medições aproximadas ciência, engenharia, modelos
Igualdade previsível na escala use tolerância use tolerância
Por que não FLOAT(12,2)? A notação não torna o valor decimal exato. O armazenamento continua em ponto flutuante binário. No MySQL moderno, não use essa forma como mecanismo de precisão.
Regra prática: dinheiro e percentuais contratuais pedem DECIMAL. Sensores e resultados estatísticos podem usar FLOAT ou, com mais precisão aproximada, DOUBLE.
DECIMAL(12,2): 10 dígitos inteiros e 2 casas decimais.
Centavos como inteiro: armazenar R$ 123,45 como 12.345 pode ser válido, mas exige unidade explícita, conversão consistente e regras de arredondamento para taxas e rateios.
0.4 CHAR, VARCHAR, TEXT e Unicode

CHAR(n)

Comprimento fixo. Bom para UF, códigos realmente fixos e hashes com tamanho estável.

uf CHAR(2)

VARCHAR(n)

Comprimento variável. Bom para nomes, e-mails, descrições curtas e códigos variáveis.

nome VARCHAR(150)

TEXT serve para conteúdo extenso, mas não deve ser a escolha automática. Limites, indexação e comportamento variam por SGBD.

Caracteres e bytes: com Unicode, um caractere pode consumir vários bytes. No MySQL moderno, utf8mb4 é a escolha usual para cobrir todo o Unicode.
MySQL 8 
nome VARCHAR(150)
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci

A collation determina regras de comparação e ordenação, inclusive sensibilidade a acentos e maiúsculas.

0.5 Dados que parecem números, mas são identificadores
CPF, CNPJ, CEP, telefone, matrícula e contrato não são quantidades. Não são somados, podem começar com zero e possuem regras próprias. Em geral, use texto.
Modelagem sem máscara 
cpf CHAR(11) NOT NULL,
cnpj CHAR(14),
cep CHAR(8),
telefone VARCHAR(20)

A máscara de exibição pode ficar na aplicação. O tipo correto não substitui validação, governança, controle de acesso e proteção de dados pessoais.

0.7 BOOLEAN, binários, UUID, JSON e ENUM

BOOLEAN

No MySQL, BOOLEAN é tratado como sinônimo de TINYINT(1). O número 1 não limita o domínio sozinho.

ativo BOOLEAN NOT NULL,
CHECK (ativo IN (0,1))

Binários

BINARY, VARBINARY e BLOB guardam bytes. Para arquivos grandes, compare BLOB com armazenamento externo e referência.

UUID

Texto é legível, mas maior. Tipo nativo ou binário pode gerar índices menores. UUID aleatório pode aumentar fragmentação de índice.

JSON

Útil para atributos flexíveis e payloads. Não deve esconder relacionamentos estáveis nem substituir modelagem relacional sem motivo.

ENUM: oferece domínio compacto em alguns SGBDs, mas aumenta acoplamento ao esquema. Uma tabela de domínio ou CHECK costuma ser mais portável.
0.8 NULL, conversões e impacto no desempenho

NULL

ausente, desconhecido ou não aplicável

''

texto presente com zero caracteres

0

valor numérico zero

'0'

texto contendo zero

WHERE gerente_id IS NULL
-- nunca: gerente_id = NULL

SELECT COALESCE(apelido, nome) AS nome_exibicao;
Conversão implícita: comparar VARCHAR com número pode causar resultados inesperados e dificultar o uso de índices. Alinhe os tipos desde a modelagem.
-- Evite tipos incompatíveis
clientes.id            BIGINT UNSIGNED
pedidos.cliente_id     BIGINT UNSIGNED
  • Tipos menores tornam índices e buffers potencialmente mais compactos.
  • Chave estrangeira deve ser compatível com a chave referenciada.
  • Funções sobre a coluna filtrada podem impedir busca eficiente por índice.
  • VARCHAR(255) em tudo não substitui a definição do domínio.
0.9 Oficina: corrija um esquema frágil
Antes 
CREATE TABLE vendas (
  id VARCHAR(255),
  cpf BIGINT,
  valor FLOAT(12,2),
  data_venda VARCHAR(30),
  ativo VARCHAR(10),
  quantidade BIGINT
);
Uma proposta melhor, dependente do domínio 
CREATE TABLE vendas (
  id BIGINT UNSIGNED PRIMARY KEY,
  cpf CHAR(11) NOT NULL,
  valor DECIMAL(15,2) NOT NULL,
  data_venda DATETIME NOT NULL,
  ativo BOOLEAN NOT NULL,
  quantidade INT UNSIGNED NOT NULL,
  CHECK (quantidade >= 0)
);
Essa não é uma resposta universal. Volume, dialeto, regras de privacidade, fuso, exclusão lógica e integração podem mudar a decisão.

Banco de dados, SGBD e linguagem SQL

Separe a linguagem, o software gerenciador e a organização lógica dos dados.

Banco de dados

Coleção organizada de dados projetada para acesso, integridade e atualização.

SGBD

Software que cria, armazena, protege, consulta e administra bancos de dados.

SGBDR

SGBD relacional, com dados estruturados em relações, normalmente apresentadas como tabelas.

SQL é a linguagem. MySQL, PostgreSQL, SQL Server, Oracle e SQLite são produtos com dialetos e capacidades distintas.
Famílias de comandos

DDL

Define estruturas: CREATE, ALTER, DROP.

DML

Manipula linhas: INSERT, UPDATE, DELETE.

DQL

Consulta dados: SELECT.

DCL

Controla privilégios: GRANT, REVOKE.

TCL

Controla transações: COMMIT, ROLLBACK.

Criação e manipulação de dados

Construa estruturas e altere dados com cautela e intenção explícita.

Tabela base 
CREATE TABLE funcionarios (
  id BIGINT UNSIGNED PRIMARY KEY,
  nome VARCHAR(120) NOT NULL,
  salario DECIMAL(12,2),
  departamento_id BIGINT UNSIGNED
);

INSERT INTO funcionarios (id,nome,salario)
VALUES (1,'Priscila',5200.00);

UPDATE funcionarios
SET salario = 5500.00
WHERE id = 1;
Comando Remove linhas? Mantém estrutura? WHERE? Observação
DELETE sim sim sim comando DML; rollback depende da transação
TRUNCATE todas sim não efeito transacional varia por SGBD
DROP remove o objeto não não elimina definição e dados
Execute primeiro como SELECT. Antes de UPDATE ou DELETE, valide o mesmo WHERE em uma consulta e confira a cardinalidade.
3

Consultas, filtros e ordenação

Recupere apenas as linhas e colunas necessárias, na ordem necessária.

Consulta composta 
SELECT nome AS funcionario, salario
FROM funcionarios
WHERE departamento_id IN (10,20)
  AND salario BETWEEN 3000 AND 8000
  AND nome LIKE 'A%'
ORDER BY salario DESC
LIMIT 5;

WHERE

Filtra linhas antes do agrupamento.

DISTINCT

Remove duplicatas do conjunto projetado.

ORDER BY

Define a ordenação do resultado final.

LIKE

% representa qualquer sequência; _, um caractere.

IS NULL

Testa ausência. Não use = NULL.

LIMIT/TOP

A sintaxe muda por dialeto. Combine com ORDER BY para um Top N determinístico.

Funções de agregação, texto, número e data

Transforme valores e produza medidas sem perder a semântica dos nulos.

Grupo Funções usuais Ponto de atenção
Agregação COUNT, SUM, AVG, MIN, MAX COUNT(coluna) ignora NULL; COUNT(*) conta linhas
Texto UPPER, LOWER, LENGTH, CONCAT, SUBSTRING nome e comportamento variam
Numérico ROUND, CEIL, FLOOR, ABS, POWER defina regra de arredondamento
Data CURRENT_DATE, NOW, DATEDIFF Datediff e intervalos variam por SGBD
Nulos COALESCE, NULLIF não substitua ausência sem compreender a regra 
SELECT departamento_id,
       COUNT(*) AS linhas,
       COUNT(salario) AS salarios_informados,
       AVG(salario) AS media_salario
FROM funcionarios
GROUP BY departamento_id;

Agrupamento e junções

Resuma grupos e combine tabelas sem duplicar ou perder linhas por acidente.

WHERE: filtra linhas antes de agrupar.
HAVING: filtra grupos depois de agregados.
SELECT d.nome, COUNT(f.id) AS quantidade
FROM departamentos AS d
LEFT JOIN funcionarios AS f
  ON f.departamento_id = d.id
WHERE d.ativo = 1
GROUP BY d.id, d.nome
HAVING COUNT(f.id) > 2
ORDER BY quantidade DESC;
JOIN Retorno Risco típico
INNER somente correspondências perder linhas sem vínculo
LEFT todas da esquerda e correspondências filtro da direita no WHERE converter o efeito em INNER
RIGHT todas da direita leitura menos intuitiva; pode reescrever como LEFT
FULL todas de ambos os lados não suportado diretamente em MySQL
CROSS produto cartesiano explosão de cardinalidade
SELF tabela com ela mesma condição de junção incorreta

Restrições, integridade e normalização

Transforme regras de negócio em garantias do banco e reduza redundâncias perigosas.

PRIMARY KEY

Identifica unicamente cada linha.

FOREIGN KEY

Garante referência válida entre relações.

UNIQUE

Evita repetição de uma chave candidata.

NOT NULL

Exige presença de valor.

CHECK

Restringe o domínio por expressão.

DEFAULT

Preenche valor quando omitido, não quando NULL é enviado.

Forma Propósito resumido
1FN valores atômicos e ausência de grupos repetitivos
2FN 1FN e nenhuma dependência parcial de chave composta
3FN 2FN e nenhuma dependência transitiva inadequada
BCNF todo determinante não trivial é chave candidata
Normalização melhora integridade, mas modelos analíticos podem usar desnormalização deliberada. A decisão deve ser explícita e mensurada.

Subconsultas e operadores de conjunto

Expresse dependências lógicas e combine resultados compatíveis.

-- Salário acima da média geral
SELECT nome, salario
FROM funcionarios
WHERE salario > (SELECT AVG(salario) FROM funcionarios);

-- Departamentos com ao menos um funcionário
SELECT d.nome
FROM departamentos d
WHERE EXISTS (
  SELECT 1 FROM funcionarios f
  WHERE f.departamento_id = d.id
);
Operador Resultado Duplicatas
UNION linhas de ambas as consultas remove
UNION ALL linhas de ambas preserva
INTERSECT linhas comuns depende da variante/dialeto
EXCEPT primeira menos segunda depende da variante/dialeto
As consultas de um operador de conjunto precisam retornar o mesmo número de colunas, em posições com tipos compatíveis.
8

Views, índices, CTEs e funções de janela

Melhore a legibilidade, a reutilização e a análise sobre conjuntos relacionados.

VIEW

Consulta nomeada apresentada como tabela virtual. Pode simplificar acesso e segurança.

INDEX

Estrutura de acesso que acelera certos filtros e joins, com custo de espaço e escrita.

CTE

Resultado nomeado dentro de uma instrução. Favorece decomposição e recursão.

WITH ranking AS (
  SELECT nome, departamento_id, salario,
         DENSE_RANK() OVER (
           PARTITION BY departamento_id
           ORDER BY salario DESC
         ) AS posicao
  FROM funcionarios
)
SELECT *
FROM ranking
WHERE posicao <= 3;
Função Empates Sequência
ROW_NUMBER cada linha recebe número diferente 1,2,3,4
RANK mesma posição 1,2,2,4
DENSE_RANK mesma posição 1,2,2,3

10

Revisão aplicada e preparação para entrevistas

Explique a decisão, escreva a consulta e verifique os casos extremos.

Checklist de consulta

  1. Entender o grão do resultado.
  2. Identificar tabelas e cardinalidades.
  3. Projetar só as colunas necessárias.
  4. Aplicar filtros e tratar NULL.
  5. Agrupar apenas quando necessário.
  6. Validar duplicações após JOIN.
  7. Ordenar e limitar de forma determinística.
  8. Analisar o plano e medir.

Perguntas essenciais

  1. DELETE, TRUNCATE e DROP?
  2. WHERE e HAVING?
  3. INNER e LEFT JOIN?
  4. COUNT(*) e COUNT(coluna)?
  5. DECIMAL e FLOAT?
  6. UNION e UNION ALL?
  7. ROW_NUMBER, RANK e DENSE_RANK?
  8. Índice composto e ordem das colunas?
Desafios de prática
  1. Obtenha os três maiores salários por departamento.
  2. Encontre clientes que não fizeram pedidos nos últimos seis meses.
  3. Deduplicate eventos, preservando o registro mais recente.
  4. Compare faturamento mensal com o mês anterior usando LAG.
  5. Revise uma tabela e justifique cada tipo de dado.
Mantra final: compreenda o grão, preserve a semântica, verifique cardinalidade, trate nulos e meça desempenho.

Glossário rápido

Termos para consulta durante o trabalho.

Cardinalidade
Quantidade de valores distintos ou relação de ocorrência entre tabelas, conforme o contexto.
Dialeto
Variação da linguagem SQL implementada por um produto.
Domínio
Conjunto de valores válidos para um atributo.
Escala
Número de dígitos após o separador decimal.
Grão
O que uma linha representa no conjunto.
Índice
Estrutura auxiliar de acesso aos dados.
Precisão
Total de dígitos de um número decimal.
Sargável
